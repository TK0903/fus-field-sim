# fus-field-sim

球面集束型 単素子超音波トランスデューサ（マウス脳 FUS-BBBO 用 自作 PZT）の
**音場を Rayleigh 積分で計算する**プロジェクト。GPU（CUDA / PyTorch）で計算する。

- 周波数・形状・コーティング厚を `config.py` で設定
- 2D（プロファイル・断面マップ）と 3D（焦点体積の等圧面）の 2 種類の計算
- 結果は設定ごとのフォルダに自動保存

## 対象デバイス

自作の球面集束 PZT 素子（マウス脳の血液脳関門開放 FUS-BBBO 用）

| 項目 | 値 |
|---|---|
| 開口直径 D | 13.0 mm（開口半径 a = 6.5 mm） |
| 曲率半径 R | 10.0 mm（= 幾何学的焦点距離） |
| 形状 | 球冠（spherical cap）、キャップ深さ h = 2.4007 mm |
| 開口半角 | asin(a/R) ≈ 40.5° |
| F 値 | R/D ≈ 0.77 → **強集束・広角。近軸近似は使わない** |

### 座標系

原点は素子の**頂点（apex, 軸上で最も凹んだ点）**、**+z を放射方向**とする。

```
    z=0 apex                    +z 放射方向 →→→
      \__                       focus
         \___                  (0,0,R)
            \____                 *
  ───────────────●────────────────┼──────  z 軸
             rim (z=h, 半径 a)     z=R  幾何焦点
```

コーティングを入れると R・a・h は実効値に置き換わる（下記）。

## コーティング厚の設定

`config.py` の `COATING_THICKNESS_UM`（µm 単位、既定 0）、または `--coating`。

素子の凹面に厚さ t を塗ると、水と接する放射面は焦点側へ t だけ寄る。
曲率中心（= 幾何学的焦点）は動かないので、**実効的な曲率半径が R−t** になる。

| モデル（`COATING_MODE`） | 内容 |
|---|---|
| `conformal`（既定） | 開口半角 θmax を保存。`R→R−t`, `a→(R−t)·sin θmax`。一様な等厚コートを想定 |
| `keep_aperture` | 開口半径 a を保存。`R→R−t`, `a` は不変。コートが素子リムを越えない場合を想定 |

**例（t = 100 µm, conformal）**

| | コート無し | コート 100 µm |
|---|---|---|
| 実効 曲率半径 R | 10.000 mm | 9.900 mm |
| 実効 開口半径 a | 6.500 mm | 6.435 mm |
| 実効 キャップ深 h | 2.4007 mm | 2.3767 mm |
| **焦点利得 G = k·h** | **15.202** | **15.050** |
| **音圧最大点 z** | **9.574 mm** | **9.450 mm** |
| -6dB 横方向ビーム幅 | 1.0508 mm | 1.0508 mm（不変） |
| -6dB 焦点体積 | 2.927 mm³ | 2.927 mm³（不変） |

**`conformal` では F 値が不変**であることに注意。R と a が同じ比率で縮むため

```
F# = R/(2a) = R/(2R·sin θmax) = 1/(2·sin θmax)   ← R に依存しない
```

となり、ビーム幅も焦点体積も変わらない。**コーティングで変わるのは
「焦点位置が t だけ手前に寄る」ことと「利得が h ∝ R に比例して下がる」ことの 2 点**
（G は R が 1 % 減れば 1 % 減る）。ビーム形状まで変えたい場合は
`keep_aperture` モードを使う（a を固定するので F 値が変わる）。

> ### ⚠ このコーティングモデルの限界
>
> **これは「放射面が t だけ移動する」という幾何的な変化だけをモデル化している。**
> 整合層の音響的な効果 —— 透過率・位相回転・インピーダンス整合・層自体の共振 ——
> は一切含まない。実際の整合層の主効果は**送信効率**側に出るため、ここで見えるのは
> 「焦点が t だけ手前に来て利得 k·h がわずかに変わる」ところまでである。
> **効率や帯域の評価には使えない。**

## 計算手法

剛体バッフル面上の Rayleigh–Sommerfeld 積分を球冠表面で数値積分する。

```
p(r) = (i·ρ·c·k·u0 / 2π) ∫∫_S  exp(-i·k·r') / r'  dS
```

時間規約は **exp(+iωt)**（よって空間項は exp(-i·k·r')）。

### 等面積サンプリング
球面では Archimedes の定理より `dA = 2πR·dz`。よって **z を等間隔に分割すれば
各リングの面積が自動的に等しくなる**。方位分割数はリングの円筒半径に比例させ、
弧長間隔が λ/6 以下になるよう λ から自動決定する。
緯度経度の単純分割は極付近が密になるので使っていない。

### 3D — なぜ marching cubes を使わないのか
音源は球冠 + 一様 u0 なので、音場は z 軸まわりに**厳密に軸対称**である。したがって:

1. 計算は **r-z 半平面だけ**でよい（3D 全格子を回すより圧倒的に安い）
2. 等圧面は「半平面の等圧線を z 軸で回した**回転体**」として厳密に得られる
   → voxel 格子由来の階段状アーティファクトが原理的に出ない
3. 体積は **Pappus の定理**で厳密積分できる： `V = ∫∫_{|p|≥thr} 2πr dr dz`

marching cubes（scikit-image）は「軸対称でない一般の場」向けの手法で、本問題では
むしろ精度が落ちる。依存も増えるため採用していない。
**「本当に軸対称か」はスクリプト内で直接 Rayleigh 積分により実測検証している**
（同一半径・異なる方位角の 4 点 → ばらつき ~1e-15 = 機械精度）。

## 検証（毎回自動で走る）

### 一次基準：焦点利得の厳密解
球冠上の全点は焦点から**厳密に等距離 R** にあるため、焦点音圧は解析的に厳密:

```
p_focus = i·ρ·c·u0·k·h·exp(-i·k·R)     →    焦点利得 G = k·h  （厳密）
```

数値積分がこの厳密値と **1 % 以内**で一致しなければ例外を投げて停止する。
音速は Marczak の式で温度依存に計算するので、**期待値もその c から再計算**して
比較している（定数を直書きしていない）。

> **補足**: 等 z 分割（Archimedes）を使うと `Σ ΔS = 2πRh` が分割数によらず厳密に
> 成立するため、**焦点利得は音源分割数に依らず機械精度で厳密に出る**。
> 分割密度が実際に効くのは**軸外**の場であり、収束テストでは軸外の点も併記している。

### そのほか
- **面積検証** `Σ dS = 2πRh`
- **グリッド収束テスト**（分割数 3, 4, 6, 8, 12 で焦点利得と軸外の値）
- **軸対称性チェック**（3D。回転体で等圧面を作る根拠）

## 現在の結果（1.5 MHz, コート 0 µm, 22 ℃, c = 1488.36 m/s）

| 項目 | 値 |
|---|---|
| 焦点利得 G | 15.202（厳密 k·h と一致） |
| -6dB 横方向ビーム幅 | 1.051 mm |
| -6dB 軸方向焦点長 (DOF) | 4.815 mm |
| 音圧最大点 | z = 9.574 mm（幾何焦点から −0.426 mm） |
| 最大サイドローブ | −16.56 dB @ x = +1.217 mm |
| **-6dB 焦点体積** | **2.927 mm³**（横 0.992 × 軸 4.763 mm、縦横比 4.8） |
| マウス脳（~500 mm³）比 | 0.585 % |
| 0.57 MPa に必要な u0 | 0.0252 m/s（表面音圧 0.0375 MPa） |

> **-20dB 体積の注意**: -20dB 面は素子へ向かう収束コーンに沿って計算領域の外へ
> 続くため、出力される値は物理的な体積ではなく**箱で切った下限値**。定量に使うなら
> `config.py` の `R_MAX_3D_MM` / `Z_MIN_3D_MM` / `Z_MAX_3D_MM` を広げること。
> スクリプトはこの切れを自動検出して警告を出す（-6dB は閉じているので確定値）。

## GPU について（注意）

計算は GPU（CUDA）で実行し、CUDA が無ければ自動的に CPU にフォールバックする。
`--cpu` で明示的に CPU 実行もできる。

> **注意**: 開発中、この環境の GPU で演算結果が壊れる現象が一度発生した
> （同一入力の演算が実行ごとに違う結果を返し、音場の値が桁違いになった）。
> その後ドライバを更新し、VRAM テストを含む各種検査はすべてクリアしているが、
> **GeForce には ECC が無く、この種の破損はハードウェアから通知されない**。
> 結果が明らかにおかしい場合（利得が異常な桁になる、図が真っ黒になる等）は
> GPU 演算の異常を疑い、`--cpu` で再計算して突き合わせること。
>
> なお焦点利得ゲート `G = k·h` は常に有効なので、焦点付近の重大な破損は
> このチェックで検出され、実行が停止する。

## 物理的仮定（結果を解釈する際の前提）

- **CW（連続波）定常解**を計算している。実駆動は 6.6 ms バースト
  （1.5 MHz で約 1e4 サイクル）なので定常状態とみなせる
- **線形伝搬**を仮定。0.57 MPa・1.5 MHz での平面波衝撃形成距離は約 17 cm で、
  焦点域の数 mm に対し十分長いため非線形歪みは無視できる
  → したがって |p| は **peak negative pressure (PNP) と等価**
- **自由音場（水中のみ）**。頭蓋・脳組織は含まない。**in-situ 値ではない**
- u0 は**振幅（peak）**であり RMS ではない。音圧も peak 表記で統一
- Rayleigh 積分は本来**平面剛体バッフル用**。曲面音源への適用は標準的な近似であり、
  **obliquity factor は省略**している
- 水の減衰（0.0022 dB/(cm·MHz²)）は既定オフ。焦点距離 10 mm・1.5 MHz では
  0.1 % 未満で無視できる
- 脱気水と通常の水で**バルク音響特性は変わらない**（溶存気体は測定実務の問題で
  あって媒質定数には影響しない）

### 駆動電圧について（重要）
出力される u0 / 表面音圧は**音響側の要求値**である。
**駆動電圧 [Vpp] への換算には素子の電気音響変換効率が別途必要**であり、
**この計算だけではアンプの電圧余裕は判定できない**。実測校正が要る。

## 3.0 / 6.0 MHz への拡張

`config.py` の `FREQ_MHZ` を変えるか、`--freq` で指定するだけ。音源分割数・
場のグリッド・期待利得 k·h はすべて λ から自動再計算され、結果フォルダも
自動で分かれる。**2D と 3D は同じ `config.py` を参照するので条件がずれることはない。**

DOF も横幅も概ね λ に比例する（同一 F# 前提）。実測値:

| f | λ | 横 -6dB | 軸 DOF | 音源点数 |
|---|---|---|---|---|
| 1.5 MHz | 0.992 mm | 1.051 mm | 4.815 mm | 7,269 |
| 3.0 MHz | 0.496 mm | 0.526 mm | 2.473 mm | 29,084 |
| 6.0 MHz | 0.248 mm | ~0.26 mm | ~1.2 mm | ~116,000 |

高周波化すると音源点数が急増するので、実行時に表示される総ペア数・推定 VRAM を
確認すること。また 6 MHz 帯では `torch.cdist` の既定モードの精度（float64 を
渡しても実質 float32 相当、誤差 ~2.4e-08）が効いてくるため、必要に応じて
`fus/rayleigh.py` で `compute_mode="donot_use_mm_for_euclid_dist"` の
明示指定を検討する。
